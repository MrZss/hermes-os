# Hermes Console Codex 开发约束 v1.0

> 用途：每次开始开发前先读这份短约束，防止产品方向偏移。

## 1. 先理解产品

Hermes Console 是：

- 桌面客户端
- Hermes Agent 的安装 / 连接 / 配置 / 会话 / 运维控制台
- 面向本地和远程 Linux 实例的图形化管理工具

它不是：

- 通用 AI 聊天 App
- IDE
- 大型运维后台
- 云服务器购买平台

## 2. 不允许做的事

1. 不允许新增一级导航
2. 不允许新增未批准页面
3. 不允许改变现有信息架构
4. 不允许引入新的页面壳层
5. 不允许把高级配置平铺到主界面
6. 不允许中英混用文案
7. 不允许新增不复用的临时组件
8. 不允许页面出现多个同权重主 CTA
9. 不允许让日志区抢走主视图
10. 不允许把白色高级主题改成暗色主主题

## 3. 现有一级导航

- 概览
- 会话
- 档案
- 提供商
- 集成
- 日志
- 备份
- 设置

任何新功能都必须挂载到上述页面之一，或挂到已有抽屉 / 模态中。

## 4. 核心对象

- 实例
- 档案
- 提供商
- 集成
- 会话
- 备份

一级对象永远是“实例”，二级核心对象是“档案”。

## 5. 组件规则

优先复用：

- Sidebar
- Topbar
- Card
- Table
- List
- Tabs
- Drawer
- Modal
- Badge
- Input
- Select
- Toggle
- Stepper
- Log Panel
- Empty State
- Split View

禁止为了单个页面临时发明新的布局体系。

## 6. 视觉规则

- 白色主体
- Light-first
- 极简、高级、安静、专业
- 低饱和状态色
- 不做赛博朋克
- 不做大渐变
- 不做游戏感
- 不做厚重黑色终端主视图

## 7. 文案规则

统一术语：

- Instance = 实例
- Profile = 档案
- Provider = 提供商
- Integration = 集成
- Session = 会话
- Backup = 备份
- Restore = 恢复
- Gateway = 网关
- Diagnostics = 诊断
- Advanced Dashboard = 高级面板

仅保留必要技术英文：OAuth、Endpoint、SSH、Docker、API、Webhook、Socket。

## 8. 每次开发前必须先说明

开始写代码前，先输出：

1. 你准备修改哪些文件
2. 这些修改对应哪个页面 / 哪条产品规则
3. 是否会影响页面结构
4. 是否会新增组件
5. 如何保证不偏离产品基线

## 9. 完成前自检

提交前必须确认：

- 没有新增页面
- 没有新增一级导航
- 没有中英混用
- 没有多个主 CTA 抢焦点
- 没有新建重复组件
- 没有把高级配置平铺到主界面
- 没有让日志区压过主要流程
- 没有破坏白色主题的高级感

## 10. 约束优先级

当临时需求、即时 prompt、或 Codex 自主建议与产品基线冲突时：

**以 PRODUCT_BASELINE_Hermes_Console_v1.md 为准。**
