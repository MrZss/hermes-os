# CODEX_GUARDRAILS.md

> 用途：每次开始开发前先读这份短约束，防止产品方向偏移。  
> 适合：Codex 会话开工前、任务拆分前、自检前。

---

## 1. 先确认你在做什么

Hermes Console 是：

- 桌面客户端
- 宗旨是一键安装 Hermes，并用最少步骤完成配置
- Hermes Agent 的安装 / 连接 / 配置 / 会话 / 运维控制台
- 面向本地实例和远程 Linux 实例的图形化管理工具

它不是：

- 通用 AI 聊天 App
- IDE
- 大型运维后台
- 云服务器购买平台
- 第二个 Hermes 官方 Dashboard

---

## 2. 硬性禁止项

1. 不允许新增一级导航
2. 不允许新增未批准页面
3. 不允许改变现有信息架构
4. 不允许引入新的页面壳层
5. 不允许把高级配置平铺到主界面
6. 不允许中英混用主标题与主要按钮
7. 不允许为了单个功能发明新的布局体系
8. 不允许页面出现多个同权重主 CTA
9. 不允许让日志区抢走主视图
10. 不允许把白色高级主题改成暗色主主题
11. 不允许把目录页做成应用商店或品牌陈列页
12. 不允许把会话页做成消费级聊天软件

---

## 3. 一级导航固定

- 概览
- 会话
- 档案
- 提供商
- 集成
- 日志
- 备份
- 设置

任何新功能都必须挂载到上述页面之一，或者挂到已有抽屉 / 模态中。

---

## 4. 核心对象固定

- 实例
- 档案
- 提供商
- 集成
- 会话
- 备份

一级对象永远是“实例”，二级核心对象是“档案”。

---

## 5. 页面核心关系

- Dashboard：全局实例总览
- 实例概览：当前实例状态与操作
- 会话：主工作页
- 档案 / 提供商 / 集成：目录 + 详情抽屉
- 日志：排查页
- 备份：恢复与维护页
- 设置：应用级设置，不是全量高级配置页

---

## 6. 组件白名单

优先复用：

- Sidebar
- Topbar
- Card
- Table
- List
- Tabs
- Drawer
- Modal
- Badge
- Button
- Input
- Select
- Toggle
- Stepper
- EmptyState
- LogPanel
- SplitView
- Timeline

禁止为了单页需求临时发明新体系。

---

## 7. 视觉与文案规则

- 白色主体，Light-first
- 极简、高级、安静、专业
- 中文优先
- 保留必要技术名词：SSH / Docker / OAuth / Endpoint / API
- 禁止中英并列标题
- 蓝色只用于当前态和主动作
- 成功 / 警告 / 危险状态全部低饱和

---

## 8. 交互规则

- 每页只保留 1 个最明显的主 CTA
- 高级配置默认折叠
- 危险操作必须走严肃确认模态
- 长任务必须显示当前步骤、进度、日志、重试或错误状态
- 抽屉承担详情，列表页承担扫描
- 模态承担短确认，不承担复杂流程

---

## 9. 开工前必须先回答

开始实现前，必须先说明：

1. 你准备修改哪些文件？
2. 这些修改对应哪一页？
3. 会不会影响壳层或信息架构？
4. 是否新增组件？
5. 新功能挂载在哪个现有页面或抽屉？
6. 如何保证不偏离 PRODUCT_BASELINE、PAGE_SPEC、UI_RULES？

如果答不清楚，就不要开始写代码。

---

## 10. 提交前自检

提交前必须自检：

1. 页面结构是否被改乱？
2. 有没有新增不在文档中的区域？
3. 是否引入新的视觉风格？
4. 中文是否统一？
5. 是否把高级配置下放到主视图？
6. 是否出现多个主 CTA？
7. 日志是否抢走了主视图？
8. 抽屉 / 模态是否遵循统一结构？

只要有 2 项不通过，就先不要提交。
