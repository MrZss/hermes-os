# Hermes Console 原生消息平台集成页收敛方案

日期：2026-04-25

## 背景

用户要求“集成只保留消息平台，并且消息平台能接入的按照原生走，原生能接入的都做好”。因此集成页从“外部接入大杂烩”收敛为 Hermes 原生 messaging gateway 平台目录。

## 范围

保留并完成原生消息平台：

- Telegram
- 微信 / Weixin
- QQ
- 飞书 / Lark

本阶段先聚焦以上 4 个高频平台，其他原生平台暂不在 UI 中展示，避免配置面过宽。

明确移出集成页：

- 程序化访问入口
- 编辑器协议入口
- 自动化回调入口
- 智能家居入口
- 扩展/插件入口

## UI/UX 约束

- 顶部只说明“原生消息平台”，不再按非消息分组。
- 每张卡片只展示平台名称、状态、健康、运行模式和接入方式。
- 配置抽屉只做 profile 级字段编辑与保存，不放实例启停或运行态维护按钮。
- Secret 字段空提交表示保持现有值。
- 已配置平台排序靠前，降低用户寻找成本。

## 数据与写入

- 桌面状态服务中的集成目录只返回原生消息平台。
- fallback mock 数据与真实状态服务保持同一平台范围。
- 保存动作只写入所选 profile 的平台字段，不再从集成页写入非消息配置。

## 验收标准

- 集成页源码不出现非消息入口文案。
- 状态服务与 fallback 数据不返回非消息入口 id。
- 4 个聚焦平台均出现在状态服务与 fallback 数据中。
- 构建通过，测试通过，浏览器页面可见原生消息平台卡片。
