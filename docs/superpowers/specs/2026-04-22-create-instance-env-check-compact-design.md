# Create Instance Env Check Compact Design

## Background

当前 `创建实例` 第 `2` 步“环境与连接检查”已经覆盖了本地与远程的预检能力，但页面存在两个明显问题：

- `当前环境信息` 与 `环境读取` 区块过大，抢走了检查结果的视觉优先级
- 本地与远程都在第 `2` 步堆了过多环境详情，导致页面高度过长，难以一屏看清

用户反馈很明确：

- 本地环境信息不应展示得这么大
- 本地和远程在环境检查界面都不应显示这么多东西
- 一屏能装下即可
- 有问题时再提示

同时，产品文档对这一页的要求也很明确：

- 必须区分本地与远程的检查逻辑
- 必须支持 `通过 / 警告 / 失败 / 可重试 / 修复建议`
- 不能把预检写成静态说明文

因此，本次设计要解决的不是“删功能”，而是把第 `2` 步改成**结果优先、环境信息后置**的紧凑预检页。

## Goal

将 `创建实例` 第 `2` 步重构为一屏优先的紧凑检查界面。

本次目标：

- 让本地与远程的环境检查页默认聚焦在“是否可继续”
- 将环境详情从常驻大卡片改为按需查看
- 保留所有必要检查项和状态表达
- 缩短页面高度，让大多数桌面窗口下可以一屏完成扫描

## Non-goals

本次不做以下事情：

- 不删除任何产品要求的检查项
- 不放宽远程实例的连接前置条件
- 不改动第 `2` 步以外的向导流程
- 不引入新的信息架构或新步骤
- 不接入真实 SSH 或本机探测能力

## Recommended Approach

采用 `C` 方案：**结果优先，只看检查**。

核心原则：

1. 第 `2` 步默认只突出显示检查结果
2. 环境信息不再做大面积常驻卡片
3. 环境详情改成次级查看入口
4. 如果没有问题，不额外堆说明文字
5. 如果有问题，直接在检查列表和提示卡中暴露

这样能最大化满足“一屏装下即可，有问题再提示”的目标。

## Layout Design

### Shared Structure

本地与远程统一采用三段布局：

1. 顶部紧凑摘要区
2. 中部检查结果主列表
3. 底部异常/风险提示区（仅在需要时出现）

页面主视觉顺序应为：

`当前目标 / 读取动作 -> 检查结果 -> 风险提示`

而不是：

`环境说明 -> 详情卡片 -> 检查结果`

### Height Budget

第 `2` 步的默认高度应控制在桌面窗口常规视口内尽量一屏可扫完。

实现目标：

- 头部摘要高度显著小于当前版本
- 本地不再显示 5 个环境信息卡片
- 远程不再显示系统版本 / Docker / 磁盘 / 端口四张结果卡
- 历史连接导入不再单独占据大面积空间

## Local Flow Design

### Default View

本地实例进入第 `2` 步后：

- 自动完成读取
- 顶部只显示一条紧凑摘要

建议内容：

- `本机`
- 平台
- 运行环境
- 一个次级动作：`重新读取`
- 一个次级入口：`查看详情`

示意表达：

`本机 · macOS · Electron` `重新读取` `查看详情`

### Removed Content

本地默认页删除以下常驻内容：

- 当前设备卡
- 系统平台卡
- 运行环境卡
- 工作目录卡
- 推荐运行方式卡
- 读取状态说明卡
- “自动读取”说明大卡

### Details Access

若用户需要查看本地详情，点击 `查看详情` 后再展开轻量详情区或抽屉。

详情区可包含：

- 设备名
- 平台
- shell / desktop shell
- Hermes 工作目录
- 推荐运行方式

默认关闭，不抢首屏。

## Remote Flow Design

### Default View

远程实例在第 `2` 步默认只显示：

- 必填连接字段
- 一个主动作：`读取环境`
- 一个次级动作：`导入历史连接`
- 读取后直接显示检查结果

### Required Fields

默认常驻字段只保留：

- 远程主机 / IP
- SSH 端口
- 用户名
- 认证方式
- 凭证输入

### Secondary Fields

以下内容不再默认常驻在主视区：

- 远程工作目录
- 远程环境摘要卡片
- 历史连接列表的完整展开块

这些内容应改成：

- 折叠的“更多设置”
- 或轻量弹层 / 下拉选择

### Removed Result Cards

远程读取成功后，不再用单独卡片展示：

- 系统版本
- Docker 状态
- 可用磁盘
- 网关端口

这些结果直接折叠进检查项描述中，让检查列表成为唯一主视图。

## Check Result Design

### Role

检查列表是第 `2` 步的主角。

### Item Content

每个检查项仅保留四个部分：

- 名称
- 状态图标 / 颜色
- 一句结果
- 必要动作按钮

### Content Rules

- `pass`：短句即可，不展开解释
- `warning`：保留原因与修复建议按钮
- `fail`：保留阻断原因与重试/读取动作

### Local Checks

本地保留这些检查项：

- 操作系统
- Docker 服务
- Hermes 工作目录
- 网络访问
- 默认端口 8080

### Remote Checks

远程保留这些检查项：

- SSH 连通性
- 用户权限
- Docker 可用性
- 磁盘空间
- 端口冲突

`可写目录` 可以继续并入“用户权限”结果说明中，不额外再做独立大信息块。

## Hint and Risk Rules

### Keep

以下内容必须保留：

- `nextStepHint`
- `environmentHint`
- 黄色 / 红色风险提示卡
- 检查项中的修复建议按钮

### Show Conditionally

风险提示区只在以下情况出现：

- 存在 `warning`
- 存在 `fail`
- 刚完成环境读取，需要给出下一步说明

如果全部通过，不再额外展示泛化说明卡。

## Interaction Design

### Local

- 进入第 `2` 步时自动完成本地读取
- 默认显示检查结果
- 点击 `查看详情` 才展开本地环境信息
- 点击 `重新读取` 刷新检查结果

### Remote

- 填写必要连接信息前，不展示远程详情卡
- 点击 `读取环境` 后直接刷新检查结果
- 点击 `导入历史连接` 填入最近连接
- 详细服务器信息只在按需查看时展开

### Continue Rule

`下一步` 的可用性规则保持不变：

- 本地：可直接继续
- 远程：只有在必要连接信息完整且成功读取环境后才能继续

## Implementation Boundaries

本次实现允许：

- 调整第 `2` 步布局结构
- 删除大卡片和常驻详情块
- 将环境信息改成折叠区 / 抽屉 / 轻量详情
- 将远程摘要并回检查结果

本次实现不允许：

- 修改检查逻辑的产品边界
- 修改第 `3-5` 步信息结构
- 增加新的向导步骤
- 用“纯文案提示”替代真实检查项

## Validation

完成后需要验证：

1. 本地第 `2` 步首屏不再出现大面积环境信息卡片
2. 远程第 `2` 步默认首屏不再出现大面积环境摘要卡片
3. 本地与远程大多数常规桌面窗口下能接近一屏看完
4. 警告项和失败项仍有明显提示与动作按钮
5. 远程实例仍必须在读取环境后才能继续下一步
6. `npm run build` 通过
7. 桌面客户端和 IAB 中手动查看无明显信息缺失

## Risks

### 风险 1：信息后置导致用户找不到详情

缓解：

- 保留明确的 `查看详情` 或 `更多设置`
- 本地和远程都采用同样的展开方式

### 风险 2：过度压缩导致检查结果难懂

缓解：

- 每个检查项保留一句结果
- `warning / fail` 必须有动作入口

### 风险 3：远程连接字段收得太狠影响填写

缓解：

- 主字段只保留“完成读取环境”所必需的项
- 次级字段移入折叠区域，不直接删除

## Rollout Order

建议实现顺序：

1. 先重构本地第 `2` 步
2. 再重构远程第 `2` 步
3. 最后统一检查列表、风险提示和 `nextStepHint`

原因：

- 本地结构更简单，适合作为紧凑布局基线
- 远程在此基础上再压缩，更容易控制风险
