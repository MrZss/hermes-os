# Hermes Console UI 迁移与收口设计

日期：2026-04-21

## 背景

当前 `ui` 目录已包含基于 Figma Make 导出的 React + Vite + Tailwind 前端源码，整体方向与 Hermes Console v1 的产品文档一致，但还存在以下问题：

- 术语与文案不统一，仍有明显中英混用
- 桌面壳层层级不够稳定，顶部状态区缺失
- 多页面处于高保真原型状态，密度、主次和组件规则未完全收口
- 抽屉、按钮、状态标签、卡片节奏尚未形成稳定系统
- 存在编译风险与原型残留代码

## 目标

本轮只做“在现有设计稿基础上的 1:1 迁移与精修”，把当前 UI 收口到“可以作为桌面端前端正式基线”的程度，为后续功能对接做准备。

## 不做的事

- 不新增页面
- 不新增一级导航
- 不改变 `概览 / 会话 / 档案 / 提供商 / 集成 / 日志 / 备份 / 设置` 的信息架构
- 不把 Hermes Console 做成 IDE、营销站或大型后台
- 不把高级配置平铺到主工作区

## 采用方案

采用“在现有 Figma Make 代码上做统一壳层 + 共享样式 + 逐页精修”的方案。

原因：

- 能最大限度保留现有设计稿的结构与视觉方向
- 能最短路径形成可冻结的 UI 基线
- 能在不重做页面的前提下统一规则，降低后续功能接入成本

## 壳层策略

### 全局壳层

- 固定左侧导航
- 固定顶部状态栏
- 固定主内容区

### 左侧导航

- 品牌区、当前实例区、工作区导航三层结构固定
- 全局态显示 `概览`、`设置`
- 实例态显示 8 个固定工作区入口
- 强化“当前实例卡片”和“工作区导航”的层级分离

### 顶部状态栏

- 全局搜索/命令入口
- 安全连接状态
- 当前档案
- 当前模型 / 提供商摘要
- 轻量快捷动作

## 视觉策略

- 主背景保持暖白与极浅灰白
- 面板和卡片保持纯白
- 分割线更浅，阴影更轻
- 蓝色仅用于当前态和主动作
- 成功、警告、危险状态使用低饱和语义色
- 通过排版、密度和留白建立重点，不靠大色块和重背景

## 术语统一

统一使用：

- 实例
- 档案
- 提供商
- 集成
- 会话
- 备份
- 恢复
- 网关
- 诊断
- 高级面板

保留必要技术词：

- SSH
- Docker
- OAuth
- Endpoint
- API
- Webhook
- Socket

## 页面改造范围

### 概览

- 收紧总览密度
- 用状态摘要、实例卡片、最近活动三段结构形成桌面控制台首页
- 保持单一主 CTA：`新建实例`

### 创建实例向导

- 保持 5 步结构不变
- 统一步骤标题、检查状态、部署中日志、成功页术语
- 强化部署摘要与安全说明

### 设置

- 收口为应用级偏好页
- 删除重复语言入口
- 用全中文文案替换 `Language`、`Light-first` 等表达

### 实例概览

- 保留结构，强化主次动作
- 稳定健康卡片节奏
- 补强最近活动与备份关系

### 会话

- 保留三栏结构
- 更清楚地区分用户消息、Agent 回复、工具调用、日志输出、最终结论
- 输入区更像桌面工作台，不像消费级聊天输入框

### 档案 / 提供商 / 集成

- 保持目录化页面
- 提升扫描效率与密度
- 统一抽屉结构：标题区、说明区、主内容区、状态区、风险区、底部按钮区

### 日志 / 备份

- 保持专业控制台气质
- 日志继续以白色技术界面呈现，不做黑底终端页
- 危险操作与普通维护动作彻底分区

## 共享组件收口

本轮允许新增少量共享 UI 片段，但不建立新的复杂组件体系：

- 统一页面头部
- 统一卡片、按钮、状态标签语义
- 统一抽屉骨架
- 统一实例 mock 数据来源

## 验证方式

- 构建通过
- 无明显编译错误
- 中文与术语统一
- 8 个固定一级导航不漂移
- 每页只保留一个最明显主 CTA
- 高级配置仍留在抽屉或次级配置区
