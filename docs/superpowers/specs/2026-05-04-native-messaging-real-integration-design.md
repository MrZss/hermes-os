# Hermes Console 原生消息平台真实对接方案

日期：2026-05-04

## 背景

AI 提供商页已经完成“真实保存 / 真实刷新 / 真实测试 / 桌面端验收”闭环。下一阶段需要把消息平台页也从“能填表”推进到“真实可保存、可回读、可引导、可验证”的稳定闭环。

当前消息平台页已经具备基础能力：

- 仅保留原生消息平台
- 已有平台目录与傻瓜式字段
- 已有微信二维码动作链路
- 已有保存后自动重启 Gateway

但还缺少像 AI 提供商页一样统一的真实状态来源、保存后回读、失败反馈和桌面端验收闭环。

## 范围

本阶段只做以下 4 个原生消息平台的真实对接：

- Telegram
- 微信 / Weixin
- QQ
- 飞书 / Lark

本阶段目标：

1. 配置真实保存
2. 保存后真实回读
3. 状态与卡片排序真实刷新
4. 微信二维码真实闭环收口
5. 错误提示与字段说明人话化
6. 桌面端实际验收

## 不在本阶段范围

- 新增更多消息平台
- 重做消息平台整体信息架构
- 把集成页改成多步 wizard
- 做消息平台真正“发一条测试消息”的跨平台通用实现
- 重构 Hermes 后端 credential 存储机制

## 产品定位

消息平台页继续保持“傻瓜式配置”的单路径体验：

> 选平台 → 填最少必填项 / 扫码 → 保存 → 自动重启 → 回来看状态

不暴露多余高级字段，不要求用户理解 Hermes 内部机制。

## 平台级策略

### Telegram

- 只保留最小必填项：
  - Bot Token
  - 用户 ID
- 保存成功后自动重启消息平台
- 保存后回读官方状态
- 对 `/sethome` 提示继续保留，但文案更直接

### 微信 / Weixin

- 主路径是二维码登录
- 抽屉里优先展示：
  - 插件前置引导
  - 生成二维码
  - 扫码状态
  - 自动保存结果
- 不把手工复制 token 当成默认路径
- 扫码成功后自动写回并刷新卡片状态

### QQ

- 只保留：
  - App ID
  - Client Secret
- 保存成功后自动重启消息平台
- 对 pairing code / approve 命令继续保留桌面端解释

### 飞书

- 只保留：
  - App ID
  - App Secret
- 保存成功后自动重启消息平台
- 保存后回读状态

## 状态来源优先级

消息平台页统一采用：

1. 官方状态回读
2. 微信二维码实时状态
3. 当前表单临时态

不允许页面靠旧静态文案假定“已启用 / 已保存”。

## UI/UX 收口要求

### 页面顶部

- 继续显示“原生消息平台”
- 当前已启用平台数量必须来自真实状态
- “保存后自动重启消息平台”文案要保留，但更口语化

### 平台卡片

- 已启用平台高亮前置
- 健康状态、运行模式、配置方式来自真实状态
- 不展示非必要技术细节

### 抽屉

- 继续只显示最小必填字段
- 必填项文案统一人话化
- Secret 留空 = 保留现有值
- 保存按钮文案、保存中状态、成功反馈、失败反馈统一

### 微信二维码

- 继续作为独立主流程
- 必须把以下状态清晰表达给用户：
  - 正在生成
  - 等待扫码
  - 已扫码，等待确认
  - 扫码成功，正在保存
  - 已保存并重启
  - 二维码过期 / 失败

## 数据与动作闭环

### 保存

统一通过：

- `updateInstanceIntegrationConfig(instanceId, payload)`

保存成功后必须：

1. 自动重启 Gateway
2. 重新读取 `getInstanceOfficialState(...)`
3. 刷新平台卡片与抽屉状态
4. 关闭抽屉或回到目录态

### 微信二维码

统一通过：

- `startInstanceWeixinQrLogin`
- `pollInstanceWeixinQrLogin`
- `cancelInstanceWeixinQrLogin`

扫码确认后必须：

1. 自动写回凭据
2. 自动重启 Gateway
3. 重新读取官方状态
4. 卡片变为已启用或展示明确失败原因

## 验收标准

### 自动验证

- 集成页相关测试通过
- 微信二维码测试通过
- 构建通过

### 桌面端验收

在 Electron 客户端中实际验证：

1. 打开消息平台页
2. 打开 Telegram / 微信 / QQ / 飞书抽屉
3. 验证必填项与文案
4. 验证微信二维码区域与状态文案
5. 验证已启用/未启用卡片高亮逻辑

## 设计结论

本阶段不重做消息平台页，而是在现有 `Integrations` 基础上补齐“真实保存 → 自动重启 → 状态回读 → 桌面验收”的闭环，使其和 AI 提供商页达到同级别完成度。
