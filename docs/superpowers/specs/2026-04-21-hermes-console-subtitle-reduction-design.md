# Hermes Console Subtitle Reduction Design

## Background

当前桌面客户端页面已经完成第一轮 UI 基线，但多个页面同时存在以下几层说明性文案：

- 页面主标题下的总说明
- 区块标题下的解释性副标题
- 卡片内部的补充说明
- 状态、风险、字段帮助类提示

这些文本叠加后会稀释页面重心，让界面更像“说明文档”而不是“桌面控制台”。用户反馈明确指出副标题过多，页面显乱。

本次设计目标是在**不改变信息架构、不改变交互流程**的前提下，系统性收掉非必须副标题。

## Goal

将 Hermes Console 的文案层级收口到“标题 + 数据/操作 + 必要提示”的桌面控制台风格。

本次目标：

- 删除非必须的页面级和区块级副标题
- 保留真正影响理解、决策和风险控制的必要文本
- 保持现有页面结构、组件风格、操作逻辑不变

## Non-goals

本次不做以下事情：

- 不调整导航结构
- 不新增或删除页面
- 不改动核心交互流程
- 不大规模重写业务文案
- 不把说明文字替换成新的长文案

## Recommended Approach

采用“结构收口”方案。

核心规则：

1. 页面主标题下的 `description` 默认删除
2. 区块标题下的解释性副标题默认删除
3. 卡片内部如果只是重复标题含义，也删除
4. 仅保留三类必要文案：
   - 状态反馈
   - 风险/警告/阻断提示
   - 字段级帮助与下一步约束提示

这比“只删一部分”更能明显改善页面杂乱感，又比“极简到只剩标题”更安全，不会伤到可理解性。

## Copy Hierarchy Rules

### 1. 必删内容

以下内容默认删除：

- `PageHeader` 下用于解释“这个页面是做什么的”的整句说明
- 区块标题下用于解释“这个区块是做什么的”的整句说明
- 已经能从标题、标签、按钮、数据本身读出来的重复解释
- 带有“v1 默认”“这里展示”“用于帮助你理解”这类介绍口吻的文案

### 2. 必留内容

以下内容必须保留：

- 错误、警告、危险操作提示
- 会影响能否继续下一步的约束说明
- 环境检查结果描述
- 表单字段存在歧义时的短帮助文案
- 时间、来源、状态、标签等元信息

### 3. 可压缩内容

以下内容不一定完全删除，但要压缩成短句或标签：

- 后续扩展提示
- 安全模型说明
- 安装方式差异说明

压缩原则：

- 优先改成一行短句
- 如果可以用状态标签表达，就不保留段落
- 如果已经有独立风险卡片，就不再重复写第二遍

## Component-level Changes

### PageHeader

- 保留 `description` 这个可选接口，避免组件 API 发生破坏性变化
- 各页面默认不再传入 `description`
- `meta` 和 `actions` 保留
- 标题与操作区之间的布局不变

原因：
这样可以低成本完成文案减法，不会引出额外组件重构风险。

## Page-level Changes

### Dashboard

删除：

- 页面主标题下的总说明
- “实例列表”下的解释性说明
- “最近活动”下的解释性说明
- “继续最近实例”卡片中的补充说明

保留：

- 活动明细
- 统计卡片中的关键数据与必要短句
- 实例卡片中的摘要、状态、元信息

说明：
首页本质是状态与入口页，不应让解释性文字占据第一视觉层。

### Settings

删除：

- 页面主标题下的总说明
- “显示语言”“应用主题”“SSH 默认项”“日志与安装偏好”下的介绍性段落
- 主题扩展卡中过长的路线说明

保留：

- 字段标签
- 当前值
- 少量不可替代的偏好状态标签

说明：
设置页应更像“偏好项面板”，而不是规则说明页。

### CreateInstance

删除：

- 第 1 步本地/远程卡片中过长的场景介绍
- 本地环境卡、远程环境卡顶部的解释性副标题
- 安装方式卡片中的冗长说明
- “高级配置”一类的介绍性副标题

保留：

- 环境检查项描述
- `environmentHint`
- `nextStepHint`
- 风险卡、警告卡、阻断提示
- 远程认证与环境读取相关的必要短提示

说明：
创建向导可以有必要提示，但不能把每一步都做成说明页。

### Onboarding

删除：

- 三种路径卡片中过长的介绍性段落

保留：

- 卡片标题
- 少量标签
- 确实影响选择的关键词

说明：
欢迎页应更快把用户送入“本地 / 远程”决策，而不是堆说明。

### Instance Pages

适用页面：

- `Overview`
- `Profiles`
- `Providers`
- `Integrations`
- `Backups`
- `Chat`

删除：

- 区块标题下重复解释
- 抽屉或侧栏顶部对当前区块的泛化介绍

保留：

- 配置摘要
- 状态摘要
- 条目详情
- 危险操作提示

说明：
实例内页已经有数据密度，副标题应只服务于状态判断和操作安全。

## Implementation Boundaries

本次实现只做“减法”和“压缩”，不改组件结构和页面布局关系。

允许的实现动作：

- 删除 `description` 传参
- 删除区块副标题节点
- 把长段落缩成短句
- 在必要时把段落替换成标签或一行提示

不允许的实现动作：

- 顺手重做页面布局
- 顺手改配色或间距体系
- 顺手改变按钮位置与流程

## Validation

完成后验证以下内容：

1. `Dashboard / Settings / CreateInstance / Onboarding / instance/*` 页面没有明显“空洞”或断裂留白
2. 页面标题、区块标题、关键数据、操作按钮仍然能独立表达页面意图
3. 创建向导仍保留足够的风险提示与下一步约束提示
4. `npm run build` 通过
5. Electron/IAB 中关键页面人工检查无明显信息缺失

## Risks

### 风险 1：删过头导致理解成本上升

缓解方式：

- 风险提示、状态反馈、字段帮助坚决保留
- 创建向导和危险操作页比普通列表页更保守

### 风险 2：删完后留白失衡

缓解方式：

- 删除段落后同步检查标题区间距
- 若出现明显空洞，只允许做小幅间距微调

## Rollout Order

建议实现顺序：

1. 先处理 `PageHeader` 使用点
2. 再处理 `Dashboard / Settings / CreateInstance`
3. 再处理 `Onboarding`
4. 最后统一清理 `instance/*`

原因：
先收最影响整体感受的页面，再做实例内页，风险最低、收益最高。
