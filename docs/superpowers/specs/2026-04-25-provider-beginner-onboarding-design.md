# AI 提供商傻瓜式接入优化设计

日期：2026-04-25

## 背景

供应商页已经按供应商卡片收敛，但仍有“自动选择”、高级配置、过多技术摘要与多处英文配置名。产品定位是“安装简单、配置简单，让没接触过 Hermes 的人最快跑通”，因此 AI 提供商配置也必须和集成页一样走必填项优先。

## 设计结论

1. **主路径固定为四步**
   - 页面顶部直接说明：选供应商 → 登录或粘贴 Key → 保存 → 测试。
   - 当前 AI 接入只显示当前 provider、模型、档案与测试状态，不展开 auth.json、credential pool 等实现细节。

2. **隐藏内部自动选择**
   - `auto` provider 只作为底层兼容状态，不进入新手可选目录。
   - UI 不出现“自动选择 / 自动检测 / 自动选择可留空”。
   - 默认模型不再特殊放行，保存前必须有明确模型值。

3. **目录按新手优先排序**
   - 已配置、当前、已验证的供应商排前。
   - 常用供应商排前：OpenAI Codex、Anthropic、DeepSeek、OpenRouter、Gemini、DashScope、Custom Endpoint。
   - 卡片只显示配置方式和推荐模型，不再平铺认证方式标签。

4. **抽屉只保留必要配置**
   - 段落顺序：供应商、认证方式、模型设置、凭据配置。
   - 单一认证方式不展示选择器，只显示说明。
   - OAuth 说明收敛为“凭据由 Hermes 管理”，按钮触发真实 OAuth。
   - API Key / Endpoint 只在对应方式下显示。
   - 移除高级配置详情块。
   - 保存按钮改为“保存并设为当前供应商”。

## 验收标准

- 供应商页源码存在 `visibleProviders`，并过滤内部 `auto` provider。
- 页面不出现“自动选择 / 自动检测 / 自动选择可留空 / 高级配置”。
- 页面出现“选供应商 → 登录或粘贴 Key → 保存 → 测试”。
- OAuth 仍调用真实 `authenticateInstanceProvider`。
- API Key provider 仍必须填写已有或新凭据才能保存。
- 测试、构建、浏览器验收通过。
