# Hermes Console 像素级与交互级 Polish 设计说明

> 日期：2026-04-22  
> 范围：前端 UI / UX 收口，不改变信息架构，不新增业务功能  
> 前提：当前 Hermes Console 已完成官方配置体系对齐，可进入功能对接前的最后一轮视觉与交互 polish。

---

## 1. 目标

本轮只解决一类问题：

- 页面已经“能用”，但还不够“像正式产品”
- 卡片、抽屉、顶栏、向导在细节上还存在节奏不统一
- 个别页面的状态信息、按钮层级、摘要块还可以更稳更干净

本轮不做：

- 不改一级导航
- 不改对象模型
- 不扩业务功能
- 不新增新页面
- 不引入新的全局组件体系

一句话：

> 这轮是体验收口，不是结构重做。

---

## 2. 范围

本轮只覆盖 5 类页面与区域：

1. 全局壳层（侧栏 / 顶栏 / 当前实例卡）
2. Dashboard / Welcome
3. 创建实例向导
4. 目录页（档案 / 提供商 / 集成 / 设置）
5. 抽屉内部节奏与状态区块

---

## 3. 设计原则

### 3.1 不改变产品定义
所有调整必须保持当前产品结构不变：

- 档案仍然是 Hermes profile
- 提供商仍然是 Hermes model/provider
- 集成仍然是 gateway / API Server / ACP / 外部接入
- 设置仍然只做应用偏好、配置摘要、维护入口

### 3.2 只收视觉与交互真实性
优先解决：

- 对齐
- 间距
- 分组节奏
- 状态层级
- 可点击与不可点击的边界清晰度
- 只读与可配置区域的视觉区分

### 3.3 页面要更“诚实”
任何看起来像已接通能力、但实际上只是占位的区域，都应弱化为：

- 只读摘要
- disabled 入口
- 更中性的提示

不允许通过视觉错觉制造“已经全接完”的假象。

---

## 4. 方案

## 4.1 全局壳层 polish

### 目标
让侧栏、顶栏、当前实例区和工作区导航更稳，不再有局部松紧不一致。

### 调整方向
- 收紧侧栏中标题、按钮、实例卡、工作区导航之间的垂直节奏
- 统一侧栏卡片与导航项圆角、边框密度与 hover 强度
- 顶栏 badge 与主按钮之间的间距再统一
- 当前实例卡与工作区导航的视觉重心更清楚

### 预期结果
- 左右壳层看起来像一个完整产品，而不是“页面 + 侧栏拼接”
- 顶栏信息更克制，不出现视觉噪点堆积

---

## 4.2 Dashboard / Welcome polish

### Dashboard
重点收：
- 首页四张摘要卡的高度感与内部节奏
- 快捷动作卡的按钮层级
- 实例卡片的上下信息密度
- 最近活动卡的列表行间距与标签压迫感

目标：
- 更像控制台首页
- 更少展示页感
- 更少“按钮分布随意”感

### Welcome
重点收：
- 本地 / 远程两张主卡的高度、标题区、徽标区和 CTA 节奏
- 右侧“关键提示”卡的信息压缩
- 首屏整体视觉重心向两张主入口卡集中

目标：
- 保持欢迎页友好，但不能松散
- 一眼看出主动作，而不是把注意力分散到说明卡

---

## 4.3 创建实例向导 polish

### 目标
让 5 步流程更像“正式安装向导”，不是“多张表单页拼接”。

### 调整方向
- 统一各 step 内容块的上边距、卡片内边距与状态块节奏
- Step 2 的检查项与提示卡再压噪一层
- Step 3 安装方式卡对齐再收紧
- Step 4 左右两列的主次关系更明确
- Step 5 摘要卡与关键提示卡视觉层级更稳定
- 底部导航区（上一步 / 下一步）与正文区的分隔感更稳定

### 特别约束
- 不再新增解释性副标题
- 不扩大高级配置
- 继续保持“未完成 provider 不可继续”的交互真实性

---

## 4.4 目录页 polish

覆盖：
- 档案页
- 提供商页
- 集成页
- 设置页

### 调整方向
- 统一卡片标题、状态标签、摘要块、底部操作区的基线对齐
- 统一卡片标题与元信息的距离
- 收紧列表页顶部与首个 section 的距离
- 统一摘要块（浅底块）的 padding、字号、边框浓度
- 统一 disabled/只读入口与可执行入口的视觉差异

### 页面专项

#### 档案页
- 强化“默认档案”状态识别，但不放大 badge 噪音
- 抽屉中的基础信息与摘要区节奏更稳

#### 提供商页
- 卡片中“认证方式 / 模型摘要”的两行关系更清楚
- 抽屉字段块更像配置摘要，而不是普通表单残留

#### 集成页
- 各组 section 的分隔节奏统一
- 卡片中状态 / 健康 / 接入类型信息密度再压一层
- 抽屉头部和配置区节奏统一

#### 设置页
- 三张卡之间的垂直关系再稳一点
- disabled 维护入口的“可点感”进一步弱化，避免误解

---

## 4.5 抽屉交互 polish

### 目标
所有抽屉看起来属于同一产品，而不是不同页面各写一套详情层。

### 调整方向
- 统一抽屉标题区高度感
- 统一首个摘要块与正文区的距离
- 统一信息块标题与内容块之间的距离
- 统一底部操作区与正文的分隔感
- 强化“只读摘要块”和“可配置字段块”的视觉差异

### 预期结果
- 抽屉一打开就知道重点在哪里
- 不靠长说明文解释结构

---

## 5. 验收标准

本轮完成后，应满足：

1. 全局顶栏、侧栏、当前实例区视觉节奏统一
2. Welcome / Dashboard 更像正式控制台，不像原型页
3. 创建实例 5 步流程的视觉与交互节奏统一
4. 档案 / 提供商 / 集成 / 设置四类目录页卡片样式更加一致
5. 抽屉内部结构统一，且不再有明显的表单残留感
6. 没有新增假交互
7. 没有新增解释性副标题噪音
8. `npm run build` 通过

---

## 6. 不做项

本轮明确不做：

- 不接真实 Hermes CLI / API
- 不做新的搜索功能
- 不做新的命令入口
- 不做新的日志实时流
- 不做新的设置项
- 不增加新的卡片区域
- 不修改导航结构
